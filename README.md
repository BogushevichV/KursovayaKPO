# Инструкция по развертыванию сервера Exam Report System

## 📋 Требования

Перед началом развертывания убедитесь, что на вашем компьютере установлены следующие программы:

### 1. Docker Desktop
- **Ссылка для скачивания:** https://www.docker.com/products/docker-desktop/
- **Версия:** Docker Desktop 4.0 или выше
- **Назначение:** Управление контейнерами PostgreSQL
- **Примечание:** После установки убедитесь, что Docker Desktop запущен

### 2. Python
- **Ссылка для скачивания:** https://www.python.org/downloads/
- **Версия:** Python 3.9 или выше (рекомендуется 3.10+)
- **Назначение:** Запуск серверного приложения
- **Важно:** При установке обязательно отметьте опцию **"Add Python to PATH"**

### 3. PyCharm (опционально, для разработки)
- **Ссылка для скачивания:** https://www.jetbrains.com/pycharm/download/
- **Версия:** PyCharm Community Edition (бесплатная) или Professional
- **Назначение:** IDE для разработки и отладки
- **Примечание:** Можно использовать любую другую IDE или редактор кода

## 🚀 Пошаговая инструкция по развертыванию

### Шаг 1: Подготовка окружения

1. **Установите Docker Desktop** и убедитесь, что он запущен
   - Проверьте запуск: откройте командную строку и выполните `docker --version`
   - Docker должен быть запущен перед выполнением следующих шагов

2. **Установите Python 3.9+**
   - При установке отметьте "Add Python to PATH"
   - Проверьте установку: `python --version`

3. **Клонируйте или скачайте проект**
   - Убедитесь, что у вас есть папка `Server` с полной структурой проекта

### Шаг 2: Настройка базы данных PostgreSQL

1. Откройте командную строку или PowerShell
2. Перейдите в папку `Server/Install`:
   ```bash
   cd Server\Install
   ```

3. Запустите скрипт настройки PostgreSQL:
   ```bash
   setup-postgres.bat
   ```

   **Что делает скрипт:**
   - Создает Docker контейнер с PostgreSQL 18
   - Настраивает базу данных `ExaminationReport`
   - Копирует файл `backup.sql` из папки `Source` в контейнер
   - Восстанавливает структуру базы данных

   **Параметры подключения (по умолчанию):**
   - **Хост:** 127.0.0.1
   - **Порт:** 5433
   - **База данных:** ExaminationReport
   - **Пользователь:** postgres
   - **Пароль:** Password1

   ⚠️ **Важно:** Если контейнер с именем `exam_pg` уже существует, скрипт выдаст ошибку. 
   Удалите существующий контейнер командой: `docker rm -f exam_pg`

### Шаг 3: Установка зависимостей Python

1. Убедитесь, что вы находитесь в папке `Server/Install`
2. Запустите скрипт установки зависимостей:
   ```bash
   install_dependencies.bat
   ```

   **Что устанавливается:**
   - Flask (веб-фреймворк)
   - Flask-CORS (поддержка CORS)
   - psycopg2-binary (адаптер PostgreSQL)
   - pytest (для тестирования)

   **Альтернативный способ (вручную):**
   ```bash
   cd Server\Install
   python -m pip install -r requirements.txt
   ```

### Шаг 4: Настройка конфигурации (опционально)

По умолчанию сервер использует настройки из `Server/Source/config.py`. 

Вы можете изменить параметры через переменные окружения:

**Для базы данных:**
```bash
set DB_NAME=ExaminationReport
set DB_USER=postgres
set DB_PASSWORD=Password1
set DB_HOST=127.0.0.1
set DB_PORT=5433
```

**Для сервера:**
```bash
set SERVER_HOST=0.0.0.0
set SERVER_PORT=5000
set DEBUG=False
```

**Для логирования:**
```bash
set LOG_DIR=Server\logs
set LOG_PREFIX=db_server
```

### Шаг 5: Запуск сервера

1. Перейдите в папку `Server`:
   ```bash
   cd Server
   ```

2. Запустите сервер:
   ```bash
   python main.py
   ```

3. Сервер запустится и будет доступен по адресу:
   - **URL:** http://127.0.0.1:5000
   - **Health check:** http://127.0.0.1:5000/api/health

4. В консоли вы увидите:
   - Информацию о подключении к БД
   - Список доступных endpoints
   - Путь к файлу логов

### Шаг 6: Проверка работоспособности

1. **Проверка health endpoint:**
   ```bash
   curl http://127.0.0.1:5000/api/health
   ```
   Или откройте в браузере: http://127.0.0.1:5000/api/health

   Ожидаемый ответ:
   ```json
   {
     "status": "ok",
     "message": "Сервер работает"
   }
   ```

2. **Проверка логов:**
   - Логи сохраняются в папке `Server/logs/`
   - Имя файла: `db_server-YYYY-MM-DD_HH-MM-SS.log`

## 🧪 Запуск тестов

### Автоматический запуск (рекомендуется)

Запустите скрипт, который автоматически запустит сервер и выполнит тесты:

```bash
cd Server\Install
run_server_and_tests.bat
```

**Что делает скрипт:**
- Запускает сервер в фоновом режиме
- Ожидает готовности сервера
- Запускает все тесты
- Останавливает сервер после завершения тестов

### Ручной запуск тестов

1. Убедитесь, что сервер запущен (или тесты запустят его автоматически)

2. Запустите тесты:
   ```bash
   cd Server
   python -m pytest tests/ -v
   ```

3. Для запуска конкретного файла тестов:
   ```bash
   python -m pytest tests/test_server_api.py -v
   python -m pytest tests/test_db_handlers.py -v
   ```

## 🔧 Устранение проблем

### Проблема: Docker не запускается
**Решение:**
- Убедитесь, что Docker Desktop установлен и запущен
- Проверьте, что виртуализация включена в BIOS
- Перезапустите Docker Desktop

### Проблема: Python не найден
**Решение:**
- Убедитесь, что Python установлен и добавлен в PATH
- Переустановите Python с опцией "Add Python to PATH"
- Проверьте: `python --version` в командной строке

### Проблема: Не удается подключиться к БД
**Решение:**
- Проверьте, что контейнер PostgreSQL запущен: `docker ps`
- Убедитесь, что порт 5433 свободен
- Проверьте параметры подключения в `Server/Source/config.py`

### Проблема: Контейнер уже существует
**Решение:**
```bash
docker rm -f exam_pg
```
Затем запустите `setup-postgres.bat` снова

### Проблема: Порт 5000 занят
**Решение:**
- Измените порт через переменную окружения: `set SERVER_PORT=5001`
- Или остановите процесс, использующий порт 5000

### Проблема: Тесты не запускаются
**Решение:**
- Убедитесь, что pytest установлен: `python -m pip install pytest`
- Проверьте, что сервер запущен (или тесты запустят его автоматически)
- Убедитесь, что база данных настроена и доступна

## 📝 Дополнительная информация

### API Endpoints

После запуска сервера доступны следующие endpoints:

**Аутентификация:**
- `GET /api/health` - проверка работоспособности
- `POST /api/auth/admin` - аутентификация администратора
- `POST /api/auth/user` - аутентификация пользователя

**Управление пользователями:**
- `POST /api/user/create` - создание пользователя
- `POST /api/user/remove` - удаление пользователя

**Управление администраторами:**
- `POST /api/admin/create` - создание администратора
- `POST /api/admin/remove` - удаление администратора

**Работа с данными:**
- `POST /api/data/save` - сохранение данных студентов и оценок
- `POST /api/data/delete_subject` - удаление предмета
- `POST /api/data/delete_group` - удаление группы
- `POST /api/data/delete_exam` - удаление экзамена
- `POST /api/data/delete_student` - удаление студента
- `GET /api/data/get_all_subjects` - получение всех предметов
- `GET /api/data/get_all_groups` - получение всех групп
- `GET /api/data/get_all_exams` - получение всех экзаменов
- `GET /api/data/get_all_students` - получение всех студентов
- `GET /api/data/get_all_users` - получение всех пользователей
- `GET /api/data/get_all_admins` - получение всех администраторов

**Отчеты:**
- `POST /api/report/find_group_students` - поиск студентов группы
- `POST /api/report/find_subject_grades` - поиск оценок по предмету

### Логирование

Все действия сервера логируются в файлы в папке `Server/logs/`:
- Формат: JSON
- Имя файла: `db_server-YYYY-MM-DD_HH-MM-SS.log`
- Логируются: HTTP запросы, SQL запросы, ошибки

### Остановка сервера

Для остановки сервера нажмите `Ctrl+C` в окне, где он запущен.

Сервер автоматически:
- Закроет соединения с БД
- Остановит Docker контейнер (если был запущен автоматически)
- Сохранит финальную запись в лог
